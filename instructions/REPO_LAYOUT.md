# Структура репозитория RTPS

Короткая памятка по корню репозитория `rtps` и назначению основных файлов и папок.

## В корне

- `.git/` - служебная папка Git. Хранит историю, ветки, refs и настройки репозитория. Удалять нельзя.
- `.github/` - GitHub Actions и прочие настройки GitHub. Сейчас здесь лежит автодеплой в `workflows/deploy.yml`.
- `.gitignore` - правила, что не отслеживать в Git. Нужен, чтобы не тащить в репо базы, кэши и временные файлы.
- `base/` - общие базы данных RTPS:
  - `common_database.db` - основная общая база RTPS
  - `web_users.db` - база пользователей и прав
- `data/` - данные веб-модулей, привязанные к конкретным сервисам:
  - `grafik_ppr_web.db` - локальная база модуля графика ремонтов
  - `web_auth.json` - веб-настройки доступа
  - `web_secret.txt` - секрет сессий
  - `grafik_auth.log` - лог входов
- `deploy/` - systemd unit-файлы и список сервисов для деплоя на сервер.
- `instructions/` - внутренняя документация по проекту.
- `rtps_common/` - общие утилиты и функции, которые используют несколько модулей.
- `web_edu/` - веб-модуль "Обучение".
- `web_alsn/` - веб-модуль "АЛСН".
- `web_grafik_ppr/` - веб-модуль графика ремонтов.
- `web_main/` - главная страница и вход в систему.
- `web_spravochnik/` - справочник/админ-модуль.
- `web_tabel/` - модуль табеля.
- `web_zamer_kp/` - модуль замера КП.
- `backup_db.py` - ручной скрипт резервного копирования баз в zip. Это вспомогательная утилита, не часть runtime.
- `start-codex.bat` - локальный батник для быстрого старта и `git pull`. Это вспомогательный файл для работы с репо.

## Что выглядит лишним

Явного мусора в корне не вижу.  
Из необязательных вещей только helper-скрипты:

- `backup_db.py`
- `start-codex.bat`

Их можно держать как удобные инструменты, но приложение без них работает.

## Что удалять не стоит

- `.git/`
- `.github/`
- `base/`
- `data/`
- `deploy/`
- все `web_*` и `rtps_common/`

## Практическое правило по БД

- если база используется несколькими модулями или общим входом, она живёт в `base/`
- если база относится к одному веб-модулю, она живёт рядом с его данными в `data/`
- `grafik_ppr_web.db` оставляем в `data/`, потому что это локальное хранилище `web_grafik_ppr`, а не shared-база всего RTPS
